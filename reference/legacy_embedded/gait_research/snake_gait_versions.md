# 蛇形步态两个版本差异说明

## 1. 文档目的

本文用于说明 `蛇形步态会偶发抽搐` 的旧版本，与当前 `蛇形步态运行稳定` 的新版本之间的差别。

对比范围主要是 `STM32` 侧源码，不涉及前端 Python。

相关文件：

- `E:\Fudan\worms\codes\USER\main.c`
- `E:\Fudan\worms\codes\HARDWARE\usartx.c`
- `E:\Fudan\worms\codes\BALANCE\system.c`

---

## 2. 结论概述

本次排查后，最终稳定版本不再抽搐，当前判断如下：

- `ESP32/TCP` 链路不是抽搐主因
- `STM32` 在运行期间没有发生隐藏复位
- 蛇形目标角本身没有出现明显跳变
- 最关键的修正，是把蛇形舵机输出从 `速度模式` 改成了 `定周期到位模式`

也就是说，旧版本更像是：

- 控制器每 `50 ms` 都向舵机发送一条新的 `速度模式` 轨迹
- 舵机内部不断重规划，长时间运行后更容易出现偶发抽动

新版本改成：

- 每个控制周期都发送一条 `定周期到位` 命令
- 舵机执行目标更明确，连续蛇形时更稳定

---

## 3. 两个版本的核心差别

### 3.1 蛇形舵机控制方式

#### 旧版本

在 `GAIT_Switch2Serpentine()` 中，蛇形控制使用：

```c
FSUS_SetServoAngleByVelocity(servo_usart, 0, targetAngle,
        250,
        150,
        150,
        0, 0);
```

特点：

- 使用的是 `按速度规划` 的控制方式
- 控制循环频率约为 `20 Hz`
- 每 `50 ms` 都会重新下发一条新轨迹
- 舵机需要不断打断并重建内部轨迹

潜在问题：

- 连续正弦运动时，轨迹重规划负担更高
- 更容易出现偶发抽动或瞬时不连续

#### 新版本

当前版本改为：

```c
FSUS_SetServoAngleByInterval(servo_usart, 0, targetAngle,
        60,
        20,
        20,
        0, 0);
```

特点：

- 使用的是 `按时间到位` 的控制方式
- 每次命令都明确规定本次动作应在多长时间内完成
- 对连续蛇形这种周期性轨迹更友好

这是本次排查中最关键、也是最终验证有效的改动。

---

### 3.2 蛇形目标角保护

#### 旧版本

旧版本直接把计算得到的 `targetAngle` 发送给舵机，没有额外保护。

如果因为计算、状态切换或偶发异常导致目标角突然偏大，就会直接传给舵机。

#### 新版本

新版本增加了：

- 相位回绕
- 单步目标角限幅
- `snakeTargetAngle` 记录

主要逻辑：

```c
targetAngle = limitServoTargetStep(targetAngle, last_servo_target, max_target_step);
```

作用：

- 防止单周期目标角变化过大
- 即使上层计算出现异常，也不会直接形成一次大幅度抽动

这部分属于 `防抖保护`，是稳定性增强，而不是最终消除抽搐的唯一原因。

---

### 3.3 高频调试输出处理

#### 旧版本

旧版本蛇形循环里曾存在高频 `printf` 调试输出，例如每个周期打印关节角度。

这种输出虽然不直接走舵机总线，但会增加系统负载和串口转发压力。

#### 新版本

新版本移除了蛇形主循环中的高频打印，只保留了低频诊断输出：

- `HB ...` 心跳
- `CLAMP ...` 仅在限幅触发时打印
- `BOOT reset=...` 上电复位原因打印

作用：

- 降低运行负载
- 保留必要诊断能力

---

### 3.4 指令串口解析稳健性

#### 旧版本

`USART1_IRQHandler()` 中原始 6 字节指令解析较脆弱，主要问题有：

- 没有充分的边界保护
- 对乱字节和错位字节容错差
- 蠕动步态参数范围校验不足

这会导致极端情况下出现误解析风险。

#### 新版本

当前版本对串口解析做了增强：

- 只有收到正确帧头才开始组帧
- 帧头错位时重新同步
- 帧长度达到后才解析
- 步态参数增加范围检查
- 帧尾错误时重新回到同步状态

作用：

- 提高抗干扰能力
- 降低偶发脏字节导致误动作的风险

这部分是 `可靠性修正`，不是本次最终止抖的唯一决定性因素，但属于必要增强。

---

### 3.5 复位诊断能力

#### 旧版本

旧版本没有明确打印 `STM32` 的复位来源，因此无法快速判断抽搐是否由 `BOR/POR/PINRST` 等造成。

#### 新版本

在 `systemInit()` 中加入了 `BOOT reset=...` 打印，读取：

- `BORRST`
- `PINRST`
- `PORRST`
- `SFTRST`
- `IWDGRST`
- `WWDGRST`
- `LPWRRST`

作用：

- 一旦现场出现“抽一下再恢复”，可以先判断是不是板子短暂复位
- 本次实测中，没有发现运行中再次出现 `BOOT reset=...`

说明抽搐不是由 `STM32` 隐藏复位引起。

---

## 4. 实测排查结果

在诊断版和稳定版测试中，观察到：

- `TCP client accepted` 正常
- `ACK` 正常收到
- `wifi=up tcp=up dropped=0`
- `HB` 周期性输出正常
- `clamp=0` 长时间保持不变
- 未抓到运行中新的 `BOOT reset=...`

因此可以排除：

- `ESP32` 网络链路抖动导致的抽搐
- `STM32` 运行中复位导致的抽搐
- 蛇形目标角突然跳变导致的抽搐

最终通过把舵机控制从 `SetServoAngleByVelocity` 改为 `SetServoAngleByInterval`，现场验证为 `不再抽搐`。

---

## 5. 版本差异总结表

| 项目 | 旧版本 | 新版本 |
| --- | --- | --- |
| 蛇形输出接口 | `FSUS_SetServoAngleByVelocity` | `FSUS_SetServoAngleByInterval` |
| 控制特点 | 连续重规划速度轨迹 | 每步明确时间到位 |
| 目标角保护 | 无单步限幅 | 有单步限幅 |
| 相位处理 | 只累加/累减 | 增加相位回绕 |
| 高频打印 | 有较重调试输出 | 仅保留低频诊断 |
| 串口指令解析 | 较脆弱 | 增加边界与重同步 |
| 复位诊断 | 无 | 有 `BOOT reset=...` |
| 实测结果 | 一段时间后偶发抽搐 | 连续运行不抽搐 |

---

## 6. 当前判断

如果只看“抽搐是否消失”这一件事，最关键的版本差异是：

1. 蛇形舵机控制从 `速度模式` 改成了 `定周期模式`
2. 同时增加了目标角保护，降低偶发异常传播到舵机的概率

因此当前稳定版可以理解为：

- `轨迹发送方式` 更适合蛇形连续运动
- `控制逻辑` 更稳
- `串口解析` 更安全
- `诊断能力` 更强

---

## 7. 后续建议

建议后续把当前稳定版作为蛇形步态基线版本保留。

如果后面继续演化，可以按下面原则处理：

- 蛇形优先使用 `SetServoAngleByInterval`
- `SetServoAngleByVelocity` 更适合单次点位移动，不适合高频重规划的连续蛇形
- 继续保留串口解析边界检查
- 继续保留低频 `HB` 和 `BOOT reset` 诊断
